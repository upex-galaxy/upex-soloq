## Criterio de nomenclatura aplicado

Formato obligatorio: `Validate <CORE> <CONDITIONAL>`

Regla de redaccion:

- `CORE`: comportamiento principal (verbo + objeto)
- `CONDITIONAL`: condicion o contexto que hace unico el escenario

## Separacion: escenarios reales vs cross-cutting

### Escenarios reales (si son test cases)

- Flujos con objetivo de negocio verificable.
- Con inicio, accion y resultado esperado.

### Cross-cutting (no son test cases independientes)

- Review visual de copy/orden/layout.
- UX de navegacion de calendario.
- Responsive/a11y/performance global.

Estos puntos se validan dentro de los test cases funcionales o en suites globales.
