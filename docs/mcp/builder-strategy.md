# MCP Builder: Session-Based Configuration Strategy

## 🎯 The Problem: Token Hell

When you configure MCP servers in AI CLI tools, **ALL configured servers load on every session**, even if you don't need them.

```
Traditional Approach (BAD):
┌─────────────────────────────────────┐
│   AI CLI Session Starts             │
│                                     │
│   Loads ALL 15 MCPs:                │
│   ✓ supabase                        │
│   ✓ postman                         │
│   ✓ playwright                      │
│   ✓ github                          │
│   ✓ atlassian                       │
│   ✓ slack                           │
│   ✓ notion                          │
│   ✓ context7                        │
│   ✓ memory                          │
│   ✓ tavily                          │
│   ✓ devtools                        │
│   ✓ sentry                          │
│   ✓ vercel                          │
│   ... (and more)                    │
│                                     │
│   Token Usage: 20,000+ tokens       │
│   ❌ Slow startup                   │
│   ❌ Expensive per message          │
│   ❌ Context window pollution       │
└─────────────────────────────────────┘
```

**The Issue**:

- Each MCP server consumes tokens in the context window
- 15 MCPs can consume 15,000-30,000 tokens before you even start
- You're paying for tools you're not using
- Slower response times
- Hitting token limits faster

## ✅ The Solution: MCP Builder

**Session-based loading**: Load ONLY the MCPs you need for your current task.

```
MCP Builder Approach (GOOD):
┌─────────────────────────────────────┐
│   Backend Task Session              │
│                                     │
│   node scripts/mcp-builder.js       │
│        backend                      │
│                                     │
│   Loads ONLY 2 MCPs:                │
│   ✓ supabase                        │
│   ✓ context7                        │
│                                     │
│   Token Usage: 2,000 tokens         │
│   ✅ Fast startup                   │
│   ✅ Low cost per message           │
│   ✅ Clean context                  │
└─────────────────────────────────────┘

Result: 90% token reduction
```

**Key Insight**: One task = One session = Specific MCP subset

| Task Type       | MCPs Needed              | Token Savings |
| --------------- | ------------------------ | ------------- |
| Backend coding  | supabase, context7       | ~85%          |
| Frontend coding | playwright, context7     | ~85%          |
| API testing     | postman, context7        | ~90%          |
| Documentation   | notion, context7, tavily | ~80%          |

## 🏗️ How It Works

### The 3-File Strategy

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  1. TEMPLATE (In Git - Safe to Share)                       │
│     templates/mcp/gemini.template.json                      │
│     • Pre-configured MCP structure                          │
│     • Variables as placeholders                             │
│     • No secrets (safe for version control)                 │
│                                                              │
│           ▼  [You copy this]                                │
│                                                              │
│  2. CATALOG (Local - Your Secrets)                          │
│     .gemini/settings.catalog.json                           │
│     • Contains ALL available MCPs                           │
│     • Has your actual API keys/tokens                       │
│     • NOT in git (.gitignore blocks it)                     │
│                                                              │
│           ▼  [MCP Builder reads this]                       │
│                                                              │
│  3. SESSION CONFIG (Auto-Generated)                         │
│     .gemini/settings.json                                   │
│     • Only MCPs for this task                              │
│     • Generated by mcp-builder.js                           │
│     • Your AI tool reads this                              │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### The Flow

```
User: node scripts/mcp-builder.js backend
         │
         ▼
     [Script loads .env]
         │
         ├── MCP_CATALOG_FILE = '.gemini/settings.catalog.json'
         ├── MCP_FILE = '.gemini/settings.json'
         └── AI_COMMAND_PATH = '/path/to/gemini' (optional)
         │
         ▼
     [Script reads catalog (with your real secrets)]
         │
         ▼
     [Resolves 'backend' profile]
         backend = ['supabase', 'context7']
         │
         ▼
     [Extracts only those 2 MCPs]
         │
         ▼
     [Writes to .gemini/settings.json]
         │
         ▼
     [Launches Gemini CLI] (if AI_COMMAND_PATH exists)
         │
         ▼
     Gemini session with ONLY 2 MCPs loaded ✓
```

## 🚀 Quick Start

### Step 1: Choose Your AI Tool

Pick your preferred CLI tool:

| Tool         | Template File                          | Catalog File (you create)       | Config File (auto-generated) |
| ------------ | -------------------------------------- | ------------------------------- | ---------------------------- |
| **Gemini**   | `templates/mcp/gemini.template.json`   | `.gemini/settings.catalog.json` | `.gemini/settings.json`      |
| **Claude**   | `templates/mcp/claude.template.json`   | `.mcp.catalog.json`             | `.mcp.json`                  |
| **OpenCode** | `templates/mcp/opencode.template.json` | `.mcp.catalog.json`             | `opencode.json`              |

### Step 2: Copy Template to Create Catalog

**For Gemini CLI**:

```bash
# Create .gemini directory if it doesn't exist
mkdir -p .gemini

# Copy template to create your catalog
cp templates/mcp/gemini.template.json .gemini/settings.catalog.json
```

**For Claude Code**:

```bash
# Copy template to create your catalog
cp templates/mcp/claude.template.json .mcp.catalog.json
```

**For OpenCode**:

```bash
# Copy template to create your catalog
cp templates/mcp/opencode.template.json .mcp.catalog.json
```

### Step 3: Add Your Real API Keys

Edit your catalog file (e.g., `.gemini/settings.catalog.json`) and **replace placeholders with actual values**:

**Before** (template):

```json
{
  "mcpServers": {
    "supabase": {
      "command": "npx",
      "args": ["-y", "@supabase/mcp-server-supabase@latest"],
      "env": {
        "SUPABASE_ACCESS_TOKEN": "${SUPABASE_ACCESS_TOKEN}"
      }
    },
    "postman": {
      "httpUrl": "https://mcp.postman.com/mcp",
      "headers": {
        "Authorization": "Bearer ${POSTMAN_API_KEY}"
      }
    }
  }
}
```

**After** (your catalog with real secrets):

```json
{
  "mcpServers": {
    "supabase": {
      "command": "npx",
      "args": ["-y", "@supabase/mcp-server-supabase@latest"],
      "env": {
        "SUPABASE_ACCESS_TOKEN": "sbp_1234567890abcdefghijklmnopqrstuvwxyz"
      }
    },
    "postman": {
      "httpUrl": "https://mcp.postman.com/mcp",
      "headers": {
        "Authorization": "Bearer pmk_abcdef123456789"
      }
    }
  }
}
```

**Important**: Your catalog file (`.catalog.json`) is already in `.gitignore` - your secrets are safe!

### Step 4: Configure Environment

Copy the example file and customize it:

```bash
# 1. Copy the template
cp .env.example .env

# 2. Edit .env with your actual paths
# The .env.example file has detailed comments for each variable
```

Your `.env` should contain:

```bash
# Your MCP catalog (contains your real secrets)
MCP_CATALOG_FILE='.gemini/settings.catalog.json'

# Where your AI tool reads config (auto-generated)
MCP_FILE='.gemini/settings.json'

# Path to AI CLI tool (OPTIONAL - leave empty for manual launch)
AI_COMMAND_PATH='/home/user/.nvm/versions/node/v22.11.0/bin/gemini'
```

**Note**: The `.env.example` file contains examples for multiple AI tools (Gemini, Claude Code, Cursor) and space for your project-specific variables.

**Find your AI_COMMAND_PATH**:

```bash
# For Gemini
which gemini

# For Claude
which claude
```

**For Different Tools**:

**Gemini CLI**:

```bash
MCP_CATALOG_FILE='.gemini/settings.catalog.json'
MCP_FILE='.gemini/settings.json'
AI_COMMAND_PATH='/path/to/gemini'
```

**Claude Code**:

```bash
MCP_CATALOG_FILE='.mcp.catalog.json'
MCP_FILE='.mcp.json'
AI_COMMAND_PATH='/usr/local/bin/claude'
```

### Step 5: Run MCP Builder

**Backend work**:

```bash
node scripts/mcp-builder.js backend
# Loads: supabase + context7
```

**Frontend work**:

```bash
node scripts/mcp-builder.js frontend
# Loads: playwright + context7
```

**Custom combination**:

```bash
node scripts/mcp-builder.js supabase,postman,github
# Loads: exactly those 3
```

**No MCPs** (clean session):

```bash
node scripts/mcp-builder.js
# Loads: none (0 token overhead)
```

**All MCPs** (NOT recommended, but available):

```bash
node scripts/mcp-builder.js full
# ⚠️ Loads ALL MCPs from catalog
# Warning will be shown
```

## 🔒 Security Model

### File Types and Git Status

```
Files IN Git (Templates - Safe to Share):
├── templates/mcp/
│   ├── gemini.template.json      # Template for Gemini
│   └── claude.template.json      # Template for Claude
└── scripts/mcp-builder.js        # The builder script

Files NOT in Git (Your Local Secrets):
├── .env                          # Your tool configuration
├── *.catalog.json                # Your catalogs with real API keys
│   ├── .gemini/settings.catalog.json
│   └── .mcp.catalog.json
│
└── Auto-generated configs:
    ├── .gemini/settings.json     # Generated by script
    └── .mcp.json                 # Generated by script
```

### Why This is Secure

1. **Templates in Git** = Structure without secrets
2. **Catalogs NOT in Git** = Your real API keys stay local
3. **Each developer** has their own catalog with their own keys
4. **No risk** of accidentally committing credentials
5. **`.gitignore`** blocks `*.catalog.json` files

### Example `.gitignore` Entry

```gitignore
# MCP catalog files (contain secrets - DO NOT COMMIT)
*.catalog.json

# MCP auto-generated config files (read by AI tools)
.mcpservers.json
.mcp.json
```

## 🎓 Best Practices

### 1. Match MCPs to Task Type

```
✅ GOOD:
Task: "Write API tests"
MCPs: postman, context7

❌ BAD:
Task: "Write API tests"
MCPs: full (loads 15 MCPs you won't use)
```

### 2. Start Minimal, Expand If Needed

```
Session 1: node scripts/mcp-builder.js backend
  ↓ (Need GitHub access mid-session)
Session 2: node scripts/mcp-builder.js backend,github
  ↓ (Done with GitHub, back to basics)
Session 3: node scripts/mcp-builder.js backend
```

### 3. Keep Your Catalog Updated

As you add more MCP servers to your catalog:

```bash
# Edit your catalog file
vim .gemini/settings.catalog.json

# Add new MCP server with your API key
# Use templates/mcp/*.template.json as reference
```

### 4. Create Custom Profiles for Your Workflow

Edit `scripts/mcp-builder.js`:

```javascript
const PROFILES = {
  // Built-in profiles...

  // Your custom workflow
  mystack: ['supabase', 'vercel', 'github', 'context7'],
};
```

Usage:

```bash
node scripts/mcp-builder.js mystack
```

### 5. Use 'full' Sparingly

The `full` profile loads **ALL** MCPs:

```bash
node scripts/mcp-builder.js full

# Output:
# ⚠️  ADVERTENCIA: Usando perfil "full"
# 📊 Esto carga TODOS los MCPs disponibles en el catálogo
# 💡 Consume muchos tokens. Considera usar perfiles específicos
# 📈 Total de MCPs a cargar: 15
```

**Valid use cases**:

- Debugging MCP configurations
- Demos/presentations
- Exploring available tools
- You genuinely need everything

**Invalid use cases**:

- Regular coding sessions (wasteful)
- When you only need 1-2 MCPs (inefficient)

## 🐛 Common Issues

### "Missing environment variables"

**Cause**: No `.env` file

**Fix**:

```bash
# Recommended: Copy the example file
cp .env.example .env

# Then edit .env with your actual paths
# The .env.example has detailed comments for each variable
```

**Quick alternative** (if you don't have .env.example):

```bash
cat > .env << EOF
MCP_CATALOG_FILE='.gemini/settings.catalog.json'
MCP_FILE='.gemini/settings.json'
# AI_COMMAND_PATH is optional
EOF
```

### "Catalog file not found"

**Cause**: You didn't create the catalog file from template

**Fix**:

```bash
# For Gemini
mkdir -p .gemini
cp templates/mcp/gemini.template.json .gemini/settings.catalog.json

# For Claude
cp templates/mcp/claude.template.json .mcp.catalog.json
```

### "Invalid MCPs: xyz"

**Cause**: Requesting MCP not in your catalog

**Fix**: Check available MCPs in your catalog

```bash
cat .gemini/settings.catalog.json | grep '"' | head -20
```

### Tool doesn't launch

**Cause**: `AI_COMMAND_PATH` is wrong or missing

**Fix**: Either correct the path OR omit it (manual mode)

```bash
# Find correct path
which gemini

# Update .env OR leave AI_COMMAND_PATH empty
```

### Secrets showing as `${VARIABLE_NAME}`

**Cause**: You forgot to replace placeholders in catalog

**Fix**: Edit catalog and add real values

```bash
# Open your catalog
vim .gemini/settings.catalog.json

# Replace ALL ${...} with actual API keys
# ${SUPABASE_ACCESS_TOKEN} → sbp_your_real_token
```

## 📚 Key Takeaways

1. **Token Hell is Real**: 15 MCPs = 20,000+ wasted tokens per session

4. **Security Built-in**: Secrets never in git, templates are safe
5. **Tool Agnostic**: Works with Gemini, Claude, Cursor, etc.
6. **Flexible Launch**: Auto-launch or manual (your choice)
7. **Pre-configured**: Use our templates, just add your API keys

```
Old Way:  All MCPs every time = Token waste
```
